# The Dealer's Game

A playable number game where the opponents and the dealer are driven by a generative AI model. It is based on the "beauty contest" game from *Alice in Borderland*.

## Game concept

Four players sit at a table: you and three AI opponents (Kaito, Rex and Mina). Each round:

1. Everyone secretly picks a whole number from 0 to 100.
2. The average of all picks is multiplied by **0.7**. This is the **target**.
3. The player closest to the target wins the round. Everyone else loses a life.
4. Everyone starts with 5 lives. A player with no lives left is eliminated.
5. The game ends when you are eliminated (defeat) or all three opponents are eliminated (victory).

From round 2 onward, the AI Dealer chooses an extra rule for each round:

| Rule | Effect |
|------|--------|
| Standard | No extra rule |
| Double penalty | Every loser loses 2 lives |
| No duplicates | Players who pick the same number as someone else cannot win and lose a life |
| Exact hit | If the winner hits the rounded target exactly, everyone else loses 2 lives |

## Where Generative AI is used

All three uses happen at runtime and depend on what the player does.

1. **AI opponents** - each opponent has a personality and receives the game history, the lives of every player and the current rule. The model reasons about what the others will pick and returns a number and a one-line thought in character.
2. **AI Dealer commentary** - after every round, and at the start and end of the game, the Dealer comments on what actually happened.
3. **AI-selected rules** - before each round, the Dealer picks one rule from a fixed menu and announces it in character.

The program, not the AI, calculates the average, the target, the winner and the lives lost, so results are always correct. The accompanying report, "Generative AI in The Dealer's Game", explains this in full.

Everything generated by the AI is labelled **AI** on screen.

## Tools used

- Python 3
- Streamlit for the interface
- `requests` for calling the model API
- `python-dotenv` for loading the API key from a `.env` file
- Groq's free hosted API running the open-source model `openai/gpt-oss-20b` (any OpenAI-compatible provider and model can be used instead)
- `pytest` for the rules tests

## How to run

1. Install Python 3.10 or newer.
2. Get a free API key from <https://console.groq.com> (API Keys, then Create API Key).
3. In the project folder, copy `.env.example` to `.env` and put your key in it:

   ```
   LLM_API_KEY=your_api_key_here
   LLM_BASE_URL=https://api.groq.com/openai/v1
   GAME_MODEL=openai/gpt-oss-20b
   ```

4. Install the dependencies and start the game:

   ```
   pip install -r requirements.txt
   python -m streamlit run app.py
   ```

5. Open the address Streamlit prints (usually <http://localhost:8501>).

If `GAME_MODEL` is not available on your account, change it to any model your provider offers.

## Running the tests

```
python -m pytest -q
```

The tests cover the game rules (target calculation, ties, each extra rule, lives and win or lose conditions) and the input validation. They do not call the AI.

## Error handling

- **Invalid input**: the player's number must be a whole number from 0 to 100. Anything else (empty, text, decimals, out of range) shows an error and the round is not played.
- **AI or API errors**: a failed request is retried, and a rate limit (HTTP 429) is retried once after a short wait. If the model still fails, the game does not crash. An opponent falls back to a number near the previous target, the Dealer falls back to a fixed line, and the rule falls back to a random one from the menu. A note on screen tells the player which parts used the fallback.
- **Malformed model output**: the reply is parsed defensively, the number is clamped to 0-100, and one retry is made before falling back.
- **Missing or rejected API key, unavailable model, no connection**: an error message at the top of the page explains the problem.

## Security note

The API key is read from the `.env` file, which is listed in `.gitignore`. Never put the key in the source code or in `.env.example`.
